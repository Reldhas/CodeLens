# Set up Gemini for CodeLens

1. Sign into [Google AI Studio](https://aistudio.google.com/api-keys) with your personal Google account. Follow the [getting-started guide](https://aistudio.google.com/docs/get-started), accept the applicable terms, and create an API key in a project you control. Use a dedicated CodeLens project/key. Never paste the key into chat or source code.
2. For a free-tier trial, keep that project on the free tier; do not enable paid billing just to test. Check the project's current model access and limits in AI Studio. Google AI Plus does not pay for API requests.
3. Open the local, ignored `.env` file. Set `AI_PROVIDER=gemini`, paste the key after `GEMINI_API_KEY=`, and leave `GEMINI_MODEL=gemini-3.5-flash` if that model is available to your project. Otherwise choose an available text model with structured JSON output. The example is configurable; a free quota is not guaranteed for every account/model.
4. Keep the generated `REVIEW_PASSWORD` private. With `LOCAL_AUTO_LOGIN=true`, the local backend creates your session automatically; the browser never reads the password from `.env`. This only works in non-production mode, with a loopback app origin and a loopback connection without forwarding headers. Public and production setups still require the password. Do not put any secret in a `VITE_` variable.
5. Run `npm run check:ai`. This sends one synthetic review (no student data) to the selected API and validates its output. It can consume quota or incur a charge on a paid project. It prints no secrets. A 403 usually indicates access/key restrictions; a 404 indicates a model mismatch; a 429 indicates exhausted quota.
6. Start `npm run dev:api` and `npm run dev` in separate terminals, then visit `http://127.0.0.1:5173`. Restart the backend whenever `.env` changes. Open Lens Review, select **Use live AI feedback** beside Submit review, and submit. The adjacent note names the provider that receives your review.

The backend sends requests to Google's fixed `generateContent` endpoint using an `x-goog-api-key` header, system instructions and a JSON response schema. It reuses the existing review validation, sessions, throttles and error handling. The browser receives the provider name for its consent text. Google responses blocked for safety or cut off at the token limit are rejected; the draft stays available for retry. The output budget is 4,096 tokens, which includes any model thinking budget. Output is validated and displayed as plain React text.

The free tier has different data-use terms from paid use. Check [Google's API terms](https://ai.google.dev/gemini-api/terms) before sending student work; use synthetic examples until your institution approves the arrangement. Read [pricing](https://ai.google.dev/gemini-api/docs/pricing) and [API key guidance](https://ai.google.dev/gemini-api/docs/api-key) for your project. Restrict the key to the Gemini API where supported, and keep it exclusively on the backend.

OpenAI remains an optional alternative: set `AI_PROVIDER=openai`, `OPENAI_API_KEY` and `OPENAI_MODEL`. There is no automatic provider fallback or hidden paid retry.
